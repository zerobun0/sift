# YouTube feed filter extension (Zen / Firefox) - research and plan

Status: **v0.1.0 built 2026-11-22 (phases 0-2 + YouTube topic chips)**, repo `browser/sift` (own private git, commit 45f2f21). Next: owner check in Zen (YT-1a), then phase 3. Deviations: vanilla TS + hand-written CSS instead of Svelte (smaller, no framework for 2 pages); no InnerTube /player fallback (bot risk) - categories come from cache, watch pages and the own API key; home-feed topics come from YouTube's own chips (owner's idea), which may make phase 4 unnecessary. Written 2026-11-22. Owner's brief: filter videos by
length and by YouTube's own category (e.g. Travel & Events) to control the home feed; Zen/Firefox
first; public on GitHub + addons.mozilla.org; smart and analytic; must look modern and hand-made,
be fast; Rust welcome where it helps.

## 1. What already exists (learn from, do not clone)

| Project | What it does well | What it lacks for us |
|---|---|---|
| **BlockTube** (amitbl, open source, AMO, updated Apr 2026) | Keyword/regex/channel/duration filters, hides Shorts and watched videos, **filters YouTube's JSON before the page renders** (no flicker), all data local | No category filtering, utilitarian UI, no analytics, no "modes" |
| **Unhook** | Clean per-element toggles (hide home feed, sidebar, Shorts, comments) | Hides whole sections, no per-video logic |
| **chocolatepcode/youtube-filter** | Duration range + title keywords across home, search, channels, sidebar, handles infinite scroll | Chrome-only load-unpacked, DOM-based |
| **SponsorBlock / DeArrow** | Mature open-source workflow: TypeScript, Firefox + Chrome builds, good options UI, community | Different job (segments/titles) - learn the project structure and release flow |
| **Flowstate** | AI topic filtering of feeds | Closed source; shows topic filtering is wanted |

**The gap nobody fills:** filtering by YouTube's own category, plus "modes" (Travel, Learn, Chill)
and a feed that refills with matching videos instead of leaving holes. That is our product.

## 2. Key technical facts (verified)

- **Duration** is already in the feed data (`lengthText` / thumbnail overlay) - free, no requests.
- **Category is NOT in feed items.** It lives in `microformat.playerMicroformatRenderer.category`
  (a name like "Travel & Events") on the watch page's `ytInitialPlayerResponse` and on InnerTube's
  `/youtubei/v1/player` response. The official Data API v3 has it as `categoryId` (needs a key;
  1 quota unit per 50 videos, 10,000 units/day - effectively unlimited for one person).
  InnerTube is undocumented and can change. Standard IDs: 1 Film & Animation, 2 Autos, 10 Music,
  15 Pets & Animals, 17 Sports, 19 Travel & Events, 20 Gaming, 22 People & Blogs, 23 Comedy,
  24 Entertainment, 25 News & Politics, 26 Howto & Style, 27 Education, 28 Science & Tech,
  29 Nonprofits.
- **YouTube's 15 categories are coarse** ("camping" is not one; it sits under Travel, People &
  Blogs or Howto). So "smart topics" need our own classifier on title + channel + description.
- **AMO rules (2026):** manifest must declare `data_collection_permissions` (we declare `none`
  unless the optional homelab sync is on); no remote code; minified/WASM builds need a source
  upload + build instructions; privacy policy only if data leaves the device.
- We already have an AMO signing key (`browser/.env.amo`, memory `home-lab-amo-signing-key`).

## 3. Features

**Core (v1)**
- Duration filter: min/max, quick presets (< 4 min, 4-20, 20-60, > 1 h), per page type.
- Category filter: include/exclude any of the 15 categories.
- Hide Shorts, live, premieres, members-only, watched, "Mix" playlists; channel allow/block lists.
- **Modes**: named presets (e.g. "Travel": Travel & Events + topic "camping", 8-40 min) switchable
  from the toolbar popup or a keyboard shortcut; optional schedule (e.g. "Learn" weekdays 9-17).
- **Refill**: when filtering empties the home feed, fetch the next feed pages in the background
  so you still see a full grid of matching videos.
- In-page status chip: "Travel · 8-40 min · 23 hidden" - click to see why each video was hidden.

**Smart + analytic (v1.5)**
- Smart topics beyond categories: local classifier (keywords + a small trained model) that tags
  videos like "camping", "cooking", "coding"; user can correct a tag and it learns.
- Analytics page (all local): what the feed offered vs what you kept, watch time by category and
  channel, "rabbit-hole" warnings, weekly summary.
- Explain mode: hover a hidden placeholder to see the rule that hid it.

**Extras I'd add**
- Blur instead of hide (peek on hover), dim watched videos.
- Title/thumbnail clickbait softener (DeArrow-style, local only).
- Import/export settings (JSON), sync between devices via `storage.sync`.
- Optional homelab category cache (`x.zerobun.com`-style endpoint) so phone + PC share lookups.
- Firefox Android support (Zen is desktop, but AMO users will ask).

## 4. Architecture

- **Manifest V3, Firefox first** (Zen = Firefox engine), Chrome build later from the same code.
- **Filter before render, not after:** a MAIN-world script wraps `fetch`/XHR for
  `/youtubei/v1/browse|next|search` and the initial `ytInitialData`, removes non-matching items
  from the JSON, and the page renders only what you want (BlockTube's proven approach: no flicker,
  no layout jump, far faster than hiding DOM nodes).
- **Category lookup pipeline:** cache first (IndexedDB, categories never change) -> categories
  learned free from every watch page you open -> optional Data API key (batched 50 per call) ->
  InnerTube `/player` fallback at a low, jittered rate. Unknown category = shown, never wrongly hidden.
- **Where Rust fits (honestly):** filtering ~30 items of JSON is microseconds in JS; Rust would not
  make that faster. Rust -> WASM earns its place in the **smart-topics classifier** (tokeniser +
  small linear/fastText-style model, ~1 MB, runs offline in a worker). TypeScript everywhere else.
- **UI:** popup + options + analytics pages in Svelte (small, fast); hand-designed (not stock
  components), dark/light, reduced-motion aware; screenshots at phone and desktop sizes before
  release. Use the UI skills (hallmark / ui-ux-pro-max / frontend-design) at design time.
- **Repo:** public GitHub, GPL-3.0 (like SponsorBlock), CI: lint (`web-ext lint`), unit tests on
  saved YouTube JSON fixtures, build + sign on tag, AMO source package generated by CI.

## 6. Risks
- YouTube changes its JSON shapes: fixtures + tests catch it; filters fail open (show, not hide).
- Too many InnerTube `/player` calls look like a bot: low rate, cache, prefer the API key.
- AMO review time for WASM/minified code: ship readable source + build docs from day one.
